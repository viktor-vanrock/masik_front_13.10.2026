# Создание бенчмарка BenchFactory

Ветка `codex/benchfactory-create` основана на `codex/benchfactory-catalog` (`c0d824b`) и включает каталог и лендинг.

## Перенос и интеграция

Страница `/create` использует композицию исходного HTML: история и закрепления, шапка с текущим статусом, переписка с шарами-аватарами, варианты ответа, карточки рекомендаций, composer и панель спецификации. Сохранены исходные шрифты, цвета, адаптивные правила, границы 1180/980/760 px и мобильный drawer над шапкой. Composer учитывает переносы строк и увеличивается до 180 px.

Транспортные hooks сохранены: WebSocket, REST-восстановление, новые server conversations, свежие intent UUID, история с пагинацией, закрепление, outbox, reconnect, повтор недоставленного сообщения и ответа. Варианты агента отправляют исходный option ID. Кнопки предыдущих вопросов и незавершённых отправок блокируются. Последняя явная сводка подтверждается обычным сообщением реальному интервьюеру.

Генерация показывает только фактические server statuses, счётчики и ETA; сохранены retry/cancel/refresh и полученные примеры. Поддержано чтение уже существующего production result и его JSONL-download. В интерфейсе нет локальных таймеров, объявляющих вымышленный успех, и не показываются старые `MOCK_*` сообщения.

## Открытые продуктовые и API-вопросы

- «Улучшить / модифицировать» оставлено без действий по согласованию.
- Multiplier и запуск production не вызываются по прямому ограничению пользователя. Подтверждение примеров не запускает масштабирование.
- Панель читает `ConversationDetailDto.specification`: сценарий, цель, домен, язык, метрику, формат заданий и название. После каждого ответа агента и reconnect запрос текущего диалога обновляется; перезагрузка и история восстанавливают сохранённую спецификацию. Исправленный снимок заменяет предыдущий, в том числе удаляет отменённые значения. Данные из Markdown и заголовка чата не угадываются. Редактирование полей нажатием пока не подключено.
- В API отсутствует сохранение отредактированных текстов примеров. Полученные задания и эталоны показаны только для чтения; checkbox позволяет просмотреть локальный отбор.
- Физического удаления чата нет в публичном API: иконка удаления не выполняет действие. Она не подменена архивированием. Существующие архивированные чаты доступны при наличии данных.
- Для email/контактов нет реализованного публичного контракта. HTML-форму, сохраняющую PII в переписку/localStorage, не подключали: она расходится с Confluence. Нужен согласованный `/api/demo/contacts` и отдельное согласие.
- Готовность, модерация и отправка на почту не объявляются локально. Они требуют фактического серверного результата/подключённого процесса.

## Проверка

Браузерные fixtures предназначены только для визуальных тестов; приложение всегда использует сервисные данные. Исходный HTML остаётся неизменным. Воспроизводимые состояния сравниваются с нативными React-компонентами через Playwright/Chromium, отдельно выполняется smoke с dev API.

Проблема закрепления на dev закрыта 30 октября. Причиной был старый backend-процесс с DTO только для title/isArchived, а не frontend или отдельная ошибка миграции. Выполнен штатный `deploy_dev` актуального backend develop `4cbc6c4` ([job 29460079](https://git.sberdevices.ru/rndbtoc/benchmark-catalog/benchmark-catalog-back/-/jobs/29460079), Helm revision 57); команда запуска включает `prisma:migrate:deploy`. На существовавшем до обновления QA-чате Chromium подтвердил HTTP 200 для `{isPinned:true}` и `{isPinned:false}`, запись/сброс pinnedDate, сохранение после reload, отсутствие дублей между закреплениями и историей, а также мобильную историю. Шесть проверок успешны, JS-ошибок нет. Чаты пользователя не изменялись.

Build, ESLint и полный Vitest: 70 файлов / 532 теста успешно. Отдельные transport-тесты покрывают fresh/resume/StrictMode, outbox, reconnect, реальные option IDs и retry. Детектор отметил исходную анимацию ширины `.prog`; она сохранена для точного соответствия HTML.

В Chromium проверены 9 состояний на 1440/1180/760/390 px (36 сценариев) и отдельно приветствие после исправления placeholder. При допуске 8 уровней RGB приветствие, старт создания, вопросы/варианты и сообщения пользователя дают 0 различающихся пикселей на всех четырёх ширинах. Строгое сравнение без допуска обнаружило 5 пикселей аватара в шапке с отличием максимум 1 уровень RGB; остальной кадр совпадает. Drawer: при том же допуске 0 на трёх ширинах и 11 пикселей на 390 px; строго — 5/5/2/88 пикселей соответственно. Карточки рекомендаций, шаги и поля примеров совпали по геометрии/стилям. Целые состояния рекомендаций/сводки/генерации/примеров отличаются там, где service contract требует принятия или отклонения каждой рекомендации, иных статусов, recovery-кнопок или не содержит спецификации. Полное совпадение этих состояний не заявляется.

Браузерные проверки транспорта с fixtures: 5/5 (option ID, блокировка повторного ответа, noop улучшения, подтверждение сводки, recommendation ID, локальный отбор примеров). Отдельно dev API подтвердил регистрацию, новый чат, reload без дубля, сохранение текста ровно один раз, второй чат и восстановление истории. Dev-агент вернул обычные Markdown-ответы без structured options/recommendations; их live выбор проверить не удалось.

Мобильное поведение включает исходное перетаскивание от левого края/закрытие свайпом. Дополнительно исправлена клавиатурная доступность drawer: закрытая панель inert, открытая удерживает фокус и возвращает его кнопке истории. Статус отправленного на проверку бенчмарка показывает «На проверке».

Независимое финальное ревью: ship в пределах описанного переноса. Замечания по статусу модерации и keyboard drawer исправлены; повторная проверка reviewer в нативном Chromium подтвердила оба исправления.

После независимого аудита 30 октября действия каждой рекомендации и её итоговый статус находятся в одной именованной группе с карточкой. Регрессионный тест на три результата проверяет конкретные recommendation ID и сохранение связи после принятия/отклонения. Chromium на 1280/390 px подтвердил отдельные доступные группы и отсутствие горизонтального переполнения. Вместе с исправлениями каталога полный прогон: build/ESLint успешны, 70 файлов / 538 тестов прошли.

Постепенное заполнение спецификации требует согласованного обновления Factory и Catalog backend: основная модель сохраняет частичные требования инструментом `update_requirements`, backend проецирует только разрешённые поля в авторизованный detail. Внутренняя история модели, инструменты и служебный контекст в браузер не передаются. Пустые/неизвестные поля остаются «не задано», счётчик и полоса показывают число заполненных строк исходного макета. Необязательный email не добавлен: контракт контактов остаётся отдельным открытым вопросом.

Проверка заполнения: build/ESLint и 70 файлов / 543 теста успешны. Реальная React-страница в Chromium получила пять последовательных снимков настоящей Factory-сессии через локальный Nest backend: частичные значения, исправление языка, удаление названия, reload и второй пустой чат. Auth, модельные ответы и Socket.IO transport в этом интеграционном прогоне — QA fixtures; публичная проекция и owner guards — настоящие. PNG заполненной панели совпал с исходным HTML без отличающихся пикселей на 1440/1280 px; на 390 px панель скрыта по исходному breakpoint, переполнения нет. Независимое ревью выявило и закрыло гонки первоначального запроса и быстрого возврата в чат. Живой запрос к настроенному модельному провайдеру остановился на ошибке авторизации до первого ответа; после выката трёх сервисов нужен smoke с рабочей конфигурацией провайдера.
