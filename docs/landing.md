# Лендинг BenchFactory

Страница `/` перенесена из предоставленного HTML BenchFactory 2. Каталог доступен по `/catalog`. Общие шапка и подвал используют исходные классы, SVG и стили; на странице чата подвал скрыт как в макете. Стили изолированы внутри `.bf-theme`, чтобы сохранить оформление существующих разделов.

## Визуальный источник

- SB Sans Display и SB Sans Text: исходные WOFF2, веса 400/500/600. JetBrains Mono 400/500 размещён локально.
- Палитра: фон `#10121b`, текст `#f2f3fc`, вторичный текст `#acb3cf`, акцент `#5865c9`, подсветка `#afb8ff`.
- Контентная ширина 1200 px, исходные адаптивные правила HTML и порядок CSS-переопределений сохранены.
- Шар использует исходные WebGL-шейдеры, SVG-шкалу и canvas частиц. Сохранены 18 предсказаний, шесть навыков, касание, перетаскивание/инерция, встряхивание, удержание и поддержка DeviceMotion. Анимации и ресурсы освобождаются при уходе со страницы.
- Сохранены scroll reveal, подсветка слов манифеста, графики, canvas сценариев и второй шар в CTA. В reduced-motion исправлен отрицательный шаг времени; невидимая шкала не обновляется.

## Согласованный функционал

- Каждый клик «Создать бенчмарк» в шапке, подвале и лендинге создаёт уникальный intent `/create?mode=create&new=<UUID>`. После авторизации он создаёт новый серверный диалог. Перезагрузка того же intent восстанавливает его без дубликата.
- Параметры и якорь целевого маршрута сохраняются при входе, регистрации и переходах между формами.
- Результат шара открывает каталог с поиском `рассужд`, `код`, `данн`, `агент`, `финанс` либо `language=ru`. ID языка берётся из серверного справочника.
- «Усилить / модифицировать» сохраняет внешний вид и не выполняет действия: решение отложено продуктом.
- Полноценная викторина MAS-UC-DEMO-003 / TC-DEMO-003 отложена по согласованию. Содержание и вид остальных страниц не переносились из HTML.

## Локальный стенд

`npm run dev -- --host 127.0.0.1 --strictPort` открывает `http://127.0.0.1:5174/`.

Для подключения к dev API настройки находятся в игнорируемом `.env.development.local`:

```dotenv
VITE_API_BASE_URL=/api
VITE_SOCKET_URL=
DEV_PROXY_TARGET=https://benchmark-catalog.dev.sberdevices.ru
DEV_PROXY_SECURE=false
DEV_PROXY_REWRITE_ORIGIN=true
```

Эти настройки применяются только Vite dev-прокси. `DEV_PROXY_SECURE=false` нужен для корпоративного сертификата; `DEV_PROXY_REWRITE_ORIGIN=true` передаёт целевой Origin в проверку dev API. Production использует прежний `/api` без этих преобразований. Для доступа к dev API нужен VPN. Диагностическая кнопка TanStack Query включается отдельно через `VITE_QUERY_DEVTOOLS=true`.

## Проверка

- В Chrome сопоставлены исходный HTML и React при 1440×1000 и 390×844. Координаты и размеры 22 ключевых блоков на каждом размере совпали; предсказания совпали, горизонтального переполнения и ошибок JavaScript нет. Проверены все восемь секций и оба шара.
- Реальный dev API: каталог и фильтр языка; гостевой CTA → регистрация → новый чат; повторная загрузка без нового пустого START_CHAT; следующий клик создаёт другой ID диалога. Проверены два серверных чата под специально созданной тестовой учётной записью `qa_landing_mvu2ngdo`.
- Чат на 1440×1000 и 390×844 занимает высоту viewport без лишнего подвала и горизонтальной прокрутки.
- `npm run build`, `npm run lint`, `npm test`: успешно; 65 файлов и 516 тестов.
- Статическая секция четырёх агентов дополнительно сравнена попиксельно в одинаковом браузере: 0 различающихся пикселей из 1 455 840.
- Локальные снимки и результаты браузерных проверок находятся в игнорируемой `.local-reports/landing/`.

Случайные частицы и непрерывное время шейдера дают разные кадры; сравнение геометрии не является заявлением о побитовом совпадении динамических кадров. Жесты физического терминала и акселерометр телефона требуют проверки на соответствующем оборудовании.
